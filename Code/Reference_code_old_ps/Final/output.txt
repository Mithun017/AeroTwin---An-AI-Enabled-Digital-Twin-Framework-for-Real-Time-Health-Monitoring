Why Version 3 — What Is Missing from v1 and v2
LeakSense Twin v1 and v2 built a solid ML pipeline, 3D viewer, and Digital Twin Generator. What they did not fully address is how an engineer actually interacts with the running system — not just to simulate leaks but to ask arbitrary questions about engine state, query historical data, inspect live values against known thresholds, and get answers in natural language backed by real data.
The Three Gaps v3 Closes
GAP 1 — DAX Query Engine:
  Engineers need to ask time-series questions like "Show me all windows where MAP_boost
  dropped more than 15% in the last 2 hours" or "What was the average residual for Zone B
  across all steady-state windows today?" — questions that need SQL-like power over sensor
  data but must be answered in milliseconds. DAX (Data Analysis Expressions) provides
  exactly this: a column-formula language optimised for time-series tabular data.
GAP 2 — Full Interactivity:
  v1/v2 let users enter threshold values and see probabilities. But the app was still
  mostly read-only. v3 makes EVERY value on the dashboard interactive: click any sensor
  reading to scrub its value, drag any chart bar to adjust and see cascade effects,
  double-click any zone to enter inspection mode, right-click any residual to query its
  history. The app becomes a live engineering workbench, not just a monitor.
GAP 3 — Real-Time Value Inspector:
  A floating inspector panel (like browser DevTools) that lets an engineer pin any sensor,
  set custom alert thresholds, overlay twin-predicted vs actual, and compare across
  multiple time windows side by side — all without leaving the dashboard.
Section 1 — DAX-Based Engine Query System
1.1 What Is DAX in This Context?
DAX (Data Analysis Expressions) is a formula language originally from Microsoft Power BI / Analysis Services. In LeakSense Twin v3, we embed a DAX-inspired query layer powered by DuckDB — a fast in-process analytical database. This gives engineers a familiar, Excel-like formula syntax to query the engine sensor database without writing SQL.
DAX vs SQL vs Natural Language — Why DAX?
SQL: powerful but unfamiliar to most engineers. "SELECT AVG(MAP_boost) FROM..." is intimidating.
Natural Language (LLM): flexible but slow, non-deterministic, sometimes wrong.
DAX: familiar to anyone who uses Excel or Power BI. Fast, deterministic, built for time-series.
DAX formula example (what the user types):
  AVERAGEX(FILTER(SensorReadings, [MAP_boost] < 200), [MAF])
  → "Average MAF in all windows where boost was below 200 kPa"
The system translates this to DuckDB SQL internally, runs it, and returns results in < 50ms.
Engineers who use Excel/Power BI can use LeakSense Twin with zero SQL training.

1.5 DAX Query Engine — Backend Implementation
backend/dax/engine.py — Full DAX-to-DuckDB translator
import duckdb, re, json
from typing import Any
from backend.dax.measures import MEASURES
class DAXEngine:
    """
    Translates DAX expressions to DuckDB SQL and executes them.
    Tables are loaded from PostgreSQL into DuckDB at startup and
    refreshed every 30 seconds from the live sensor stream.
    """
    def __init__(self, pg_dsn: str):
        self.conn = duckdb.connect(":memory:")  # in-process, no disk
        self._load_tables_from_postgres(pg_dsn)
        self._register_measures()
    def _load_tables_from_postgres(self, pg_dsn: str):
        """Load last 24h of data from PostgreSQL into DuckDB tables."""
        # DuckDB can read from Postgres directly via postgres_scan extension
        self.conn.execute("INSTALL postgres_scanner; LOAD postgres_scanner;")
        tables = {
            "SensorReadings": "SELECT * FROM sensor_readings WHERE timestamp > NOW()-INTERVAL 24 HOUR",
            "TwinResiduals":   "SELECT * FROM twin_residuals WHERE timestamp > NOW()-INTERVAL 24 HOUR",
            "LeakEvents":      "SELECT * FROM leak_events WHERE detected_at > NOW()-INTERVAL 7 DAY",
            "ThresholdChecks": "SELECT * FROM threshold_checks WHERE checked_at > NOW()-INTERVAL 24 HOUR",
            "EngineSpecs":     "SELECT * FROM engine_specs",
        }
        for name, sql in tables.items():
            self.conn.execute(f"""
                CREATE OR REPLACE TABLE {name} AS
                SELECT * FROM postgres_scan('{pg_dsn}', '{sql}')""",
            )
    def _register_measures(self):
        """Pre-compute all measures as views."""
        for name, formula in MEASURES.items():
            sql = self._dax_to_sql(formula)
            self.conn.execute(f"CREATE OR REPLACE VIEW [_{name}] AS {sql}")
    def query(self, dax_expression: str, timeout_ms: int = 5000) -> dict:
        """
        Execute a DAX expression and return results as dict.
        Supports: scalar values, table results, and named measure references.
        """
        try:
            # Expand named measures
            expanded = self._expand_measures(dax_expression)
            # Translate DAX to SQL
            sql = self._dax_to_sql(expanded)
            # Execute with timeout
            result = self.conn.execute(f"SET statement_timeout={timeout_ms}; {sql}").df()
            return {
                "success": True,
                "rows": result.to_dict(orient="records"),
                "columns": list(result.columns),
                "row_count": len(result),
                "is_scalar": len(result)==1 and len(result.columns)==1,
                "scalar_value": result.iloc[0,0] if len(result)==1 and len(result.columns)==1 else None
            }
        except Exception as e:
            return {"success": False, "error": str(e), "rows": [], "columns": []}
    def _expand_measures(self, expr: str) -> str:
        """Replace [MeasureName] references with their formula."""
        for name, formula in MEASURES.items():
            expr = expr.replace(f"[{name}]", f"({formula})")
        return expr
    def _dax_to_sql(self, dax: str) -> str:
        """
        Core DAX-to-SQL translation.
        Handles: CALCULATE, FILTER, AVERAGEX, SUMX, COUNTX,
                 MINX, MAXX, IF, DIVIDE, TOPN, DATESBETWEEN,
                 DATEADD, VALUES, ALL, RANKX, CORR, STDEV, PERCENTILE
        """
        sql = dax.strip()
        # Table name normalisation
        sql = re.sub(r"\bSensorReadings\b", "SensorReadings", sql)
        sql = re.sub(r"\bLeakEvents\b", "LeakEvents", sql)
        sql = re.sub(r"\bTwinResiduals\b", "TwinResiduals", sql)
        sql = re.sub(r"\bThresholdChecks\b", "ThresholdChecks", sql)
        sql = re.sub(r"\bEngineSpecs\b", "EngineSpecs", sql)
        # Column references: [colname] → "colname"
        sql = re.sub(r"\[([\w_]+)\]", r'"\1"', sql)
        # CALCULATE(expr, filter) → SELECT expr FROM table WHERE filter
        sql = re.sub(
            r"CALCULATE\((.+?),\s*FILTER\(([\w]+),\s*(.+?)\)\)",
            r"SELECT \1 FROM \2 WHERE \3",
            sql, flags=re.DOTALL)
        # AVERAGEX(FILTER(T,cond),expr) → SELECT AVG(expr) FROM T WHERE cond
        sql = re.sub(
            r"AVERAGEX\(FILTER\(([\w]+),\s*(.+?)\),\s*(.+?)\)",
            r"SELECT AVG(\3) FROM \1 WHERE \2",
            sql, flags=re.DOTALL)
        # COUNTX(FILTER(T,cond),1) → SELECT COUNT(*) FROM T WHERE cond
        sql = re.sub(
            r"COUNTX\(FILTER\(([\w]+),\s*(.+?)\),\s*1\)",
            r"SELECT COUNT(*) FROM \1 WHERE \2",
            sql)
        # MAXX/MINX(FILTER...) → SELECT MAX/MIN(...)
        sql = re.sub(r"MAXX\(FILTER\(([\w]+),(.+?)\),(.+?)\)",
                    r"SELECT MAX(\3) FROM \1 WHERE \2", sql)
        sql = re.sub(r"MINX\(FILTER\(([\w]+),(.+?)\),(.+?)\)",
                    r"SELECT MIN(\3) FROM \1 WHERE \2", sql)
        # STDEV → STDDEV_POP
        sql = sql.replace("STDEV(", "STDDEV_POP(")
        # CORR(a,b) → CORR(a,b) (DuckDB supports this natively)
        # PERCENTILE(table, pct, expr)
        sql = re.sub(
            r"PERCENTILE\(([\w]+),([\d.]+),(.+?)\)",
            r"SELECT PERCENTILE_CONT(\2) WITHIN GROUP (ORDER BY \3) FROM \1",
            sql)
        # DIVIDE(num, denom, alt) → CASE WHEN denom=0 THEN alt ELSE num/denom END
        sql = re.sub(
            r"DIVIDE\((.+?),(.+?),(.+?)\)",
            r"CASE WHEN (\2)=0 THEN \3 ELSE (\1)/(\2) END",
            sql)
        # IF(cond, true, false) → CASE WHEN cond THEN true ELSE false END
        sql = re.sub(
            r"IF\((.+?),(.+?),(.+?)\)",
            r"CASE WHEN \1 THEN \2 ELSE \3 END",
            sql)
        # DATEADD(col, n, unit) → col + INTERVAL n unit
        sql = re.sub(
            r"DATEADD\((.+?),(-?\d+),"(.+?)"\)",
            r"(\1 + INTERVAL \2 \3)",
            sql)
        # TOPN(n, table, expr, dir) → ORDER BY expr dir LIMIT n
        sql = re.sub(
            r"TOPN\((\d+),([\w]+),(.+?),(ASC|DESC)\)",
            r"SELECT * FROM \2 ORDER BY \3 \4 LIMIT \1",
            sql)
        # Bare scalar: AVERAGE([col]) with no SELECT yet
        if not sql.strip().upper().startswith("SELECT"):
            sql = re.sub(r"AVERAGE\(([\w."]+)\)",
                        r"SELECT AVG(\1) FROM SensorReadings", sql)
        return sql
    def refresh_tables(self):
        """Call this every 30s from a background task to refresh DuckDB cache."""
        self._load_tables_from_postgres(self._pg_dsn)

    ]}
# POST /api/dax/validate — Validate DAX syntax without executing
@router.post("/validate")
async def validate_dax(body: dict):
    """Parses and validates a DAX expression without running it."""
    expr = body.get("expression", "")
    try:
        sql = dax_engine._dax_to_sql(dax_engine._expand_measures(expr))
        dax_engine.conn.execute(f"EXPLAIN {sql}")
        return {"valid": True, "translated_sql": sql}
    except Exception as e:
        return {"valid": False, "error": str(e)}
# GET /api/dax/suggestions — Autocomplete DAX suggestions for the console UI
@router.get("/suggestions")
async def dax_suggestions(prefix: str = ""):
    """Returns DAX function and measure name suggestions for the query console."""
    funcs = ["CALCULATE","FILTER","AVERAGEX","SUMX","COUNTX","MINX","MAXX",
             "IF","DIVIDE","TOPN","DATESBETWEEN","DATEADD","VALUES","ALL",

    all_items = funcs + [f"[{m}]" for m in measures] + tables
    filtered = [x for x in all_items if prefix.upper() in x.upper()]

Section 2 — Full Interactivity Layer
2.1 The Interactivity Philosophy
v1 and v2 built a monitoring dashboard. v3 makes it an engineering workbench. Every number on the screen becomes a control surface. Engineers should be able to manipulate the engine state directly and see what happens — like a flight simulator for diesel engines.
Interactivity Principles
1. CLICK any value to scrub it — click the "842" MAF reading and drag left/right to change it
2. DRAG any bar in the probability chart to set a probability and see what sensor values would cause it
3. DOUBLE-CLICK any zone card to enter full-screen inspection mode for that zone
4. RIGHT-CLICK any sensor gauge to open context menu: query history, set alert, compare windows
5. HOVER any residual value to see the twin-predicted vs actual breakdown as a tooltip
6. PIN any sensor to the persistent Inspector Panel — values persist across navigation
7. COMPARE: drag sensor to comparison tray — overlay up to 3 time windows side by side
8. ANNOTATE: click any point on the timeline to leave an engineer note (stored in DB)

// Add to the flow canvas (2D overlay), after drawFlows()
// Track which path segment is being hovered
let hoveredFlowPath = null;
let isDraggingFlow = false;
let flowDragStartY = 0;
let flowDragLeak = 0;  // 0.0 to 1.0 = 0% to 100% restriction

  if (isDraggingFlow) {
    // Calculate restriction from drag distance
    const dy = e.clientY - flowDragStartY;
    flowDragLeak = Math.max(0, Math.min(0.99, dy / 100));
    // Apply to threshold panel in real-time

    drawFlowWithRestriction(hoveredFlowPath, flowDragLeak);
    return;
  }
  // Check if mouse is near any flow path
  const nearPath = getFlowPathAtPoint(e.clientX, e.clientY, 8);
  if (nearPath !== hoveredFlowPath) {
    hoveredFlowPath = nearPath;
    fCvs.style.cursor = nearPath ? "ns-resize" : "default";
    if (nearPath) showFlowTooltip(e.clientX, e.clientY, nearPath);
    else hideFlowTooltip();
  }
});
fCvs.addEventListener("mousedown", (e) => {
  if (hoveredFlowPath) {
    isDraggingFlow = true;
    flowDragStartY = e.clientY;
    APP.autoRot = false;
  }
});
window.addEventListener("mouseup", () => {
  if (isDraggingFlow && flowDragLeak > 0.1) {
    // Convert flow restriction to zone leak
    const zoneMap = {intake:"A", boost:"B", cac:"C", exhaust:"D", fuel:"F"};
    const zone = zoneMap[hoveredFlowPath.name];
    if (zone) {
      APP.severity = flowDragLeak < 0.15 ? 1 : flowDragLeak < 0.35 ? 2 : 3;

  isDraggingFlow = false;
  flowDragLeak = 0;

function applyFlowRestriction(path, restriction) {
  // Update sensor values in threshold panel based on restriction
  if (!path) return;
  if (path.name === "boost") {
    APP.thresholdValues.MAP_boost = 218 * (1 - restriction * 0.8);
    APP.thresholdValues.MAP_cac   = 213 * (1 - restriction * 0.9);
  } else if (path.name === "intake") {
    APP.thresholdValues.MAF = 842 * (1 - restriction);
  } else if (path.name === "exhaust") {
    APP.thresholdValues.T_exh_man = 512 * (1 - restriction * 0.15);
  }
  // Live update threshold preview
  updateThresholdPreview();
}
function drawFlowWithRestriction(path, restriction) {
  // Draw a "pinch" visual on the restricted flow line
  if (!path || restriction < 0.05) return;
  const midPt = projPt(path.pts[Math.floor(path.pts.length/2)]);
  fctx.save();
  fctx.translate(midPt.x, midPt.y);
  // Draw constriction arrows
  const gap = (1-restriction)*14;
  fctx.strokeStyle = `rgba(255,34,68,${0.4+restriction*0.5})`;
  fctx.lineWidth = 2; fctx.shadowColor = "#FF2244"; fctx.shadowBlur=8;
  fctx.beginPath(); fctx.moveTo(-12,0); fctx.lineTo(-gap,0); fctx.stroke();
  fctx.beginPath(); fctx.moveTo(12,0);  fctx.lineTo(gap,0);  fctx.stroke();
  // Restriction percentage label
  fctx.fillStyle = "#FF2244"; fctx.font="bold 10px Share Tech Mono";
  fctx.textAlign="center";
  fctx.fillText(`${(restriction*100).toFixed(0)}% restricted`, 0, -16);
  fctx.restore();
}
3.3 Heat Map Overlay Mode
3D viewer JS — Toggle heat map mode (add to tick loop)
let heatMapMode = false;
function toggleHeatMap() {
  heatMapMode = !heatMapMode;
  document.getElementById("btn-heat").classList.toggle("on", heatMapMode);
  if (!heatMapMode) {
    // Reset all materials to originals
    EG.traverse(c => {
      if (c.isMesh && c._originalColor) {
        c.material.color.setHex(c._originalColor);
        c.material.emissiveIntensity = c._originalEI || 0;
      }
    });
    return;
  }
  // Store original colours on first activation
  EG.traverse(c => {
    if (c.isMesh && !c._originalColor) {
      c._originalColor = c.material.color.getHex();
      c._originalEI = c.material.emissiveIntensity || 0;
    }
  });
}
function applyHeatMap(sensors) {
  if (!heatMapMode) return;
  // Map temperature sensors to 3D zones
  const tempMap = {
    1: sensors.T_cac_out,   // intake zone temp
    2: sensors.T_cac_out,   // charge air zone temp
    3: sensors.T_exh_man,   // exhaust zone temp (hottest)
    4: sensors.T_cac_out + 20, // fuel zone (slightly warm)
  };
  const T_min = 40, T_max = 600;  // engineering range
  Object.entries(tempMap).forEach(([zone, T]) => {
    const t = Math.max(0, Math.min(1, (T - T_min)/(T_max - T_min)));
    // Interpolate blue(cool) → green → yellow → red(hot)
    let r, g, b;
    if (t < 0.5) { r=0; g=Math.round(t*2*255); b=Math.round((1-t*2)*255); }
    else { r=Math.round((t-0.5)*2*255); g=Math.round((1-(t-0.5)*2)*255); b=0; }
    const hexCol = (r<<16)|(g<<8)|b;
    ZP[parseInt(zone)].forEach(p => {
      const apply = m => {
        if (m.isMesh && m.material) {
          m.material.color.setHex(hexCol);
          m.material.emissiveIntensity = t * 0.3;
          m.material.emissive = new THREE.Color(hexCol);
        }
      };
      if (p.isGroup) p.children.forEach(apply); else apply(p);
    });
  });
}
